# 保留附魔等级并按复制语义返还武器

## 背景

原实现只把附魔类名写入饰品，返还时按武器 ID 创建新实例并创建一级附魔。原版把同类锻造和银河之魂次数保存在单个附魔对象的 `Level` 中，因此两次银河之魂会被错误恢复成一次。原版 `AddEnchantment` 还会合并同类锻造、替换已有主附魔，不适合还原已存在的列表状态。

## 决定

1. 新格式持久化附魔完整类型名、程序集简单名和等级，并保留旧类名列表的只读兼容。
2. 恢复时逐项创建同类型、同等级附魔，直接加入目标列表后调用 `ApplyTo`，与原版复制武器的语义一致。
3. 新熔铸数据必须在返还旧武器前完成序列化和验证；写入饰品时保存受影响键的旧值，失败即回滚。
4. 旧格式缺失的等级不可猜测，按一级恢复并向玩家和日志明确警告；简单类名优先匹配原版，多个 Mod 类型同名时拒绝返还而非任选其一。
5. 新签名解析失败时清空战斗缓存并显式报错，禁止继续使用上一枚戒指的数据。
6. 当前格式的武器字段和附魔条目必须完整；缺失、孤立、坏 JSON 或附魔类型无法实例化均按损坏数据处理。菜单和悬浮说明必须保持可用，且菜单禁止用新熔铸覆盖损坏的原始 `modData`。

## 备选

- 继续只保存类名：无法区分一级、二级和三级，拒绝。
- 恢复时重复调用 `AddEnchantment`：会改变重复附魔和多个主附魔的列表结构，拒绝。
- 自动推断旧银河之魂等级：一颗和两颗银河之魂不改变武器属性，没有可靠证据，拒绝。

## 后果

新熔铸武器可以无损保留原版及可加载 Mod 附魔的等级，包括高于附魔实现默认上限、但已真实存在于原武器快照中的正等级。旧格式仍能返还，但历史等级已经不可逆丢失。移除提供 Mod 附魔类型的程序集、附魔无法构造或旧类名存在歧义时，返还会显式失败并保留饰品中的旧数据；损坏数据不会继承其他戒指的战斗光环，也不会阻止菜单关闭或戒指悬浮说明。
