# 跨图路线模型

## 问题

如何表示和计算室外地图之间的出口选择、路线距离和目标可达性，才能稳定支持 11 个目的地并避免导航期间实时全图搜索？

## 答案

采用“运行时读取普通 Warp 拓扑、按出口节点加权规划、局部路径结果缓存”的路线模型，不把整张路线表硬编码进 DLL，也不在马匹移动期间重复进行全图搜索。

### 路线图

- 启动世界或第一次导航前，从当前游戏地图的 `Warp` 属性构建有向出口图；每条边保留完整身份：源地图、源出口 tile、目标地图、目标入口 tile。
- 只纳入当前室外白名单中的普通 `Warp`。`NPCWarp`、室内门 Action、矿洞/洞穴、公交、矿车、图腾、船和其他特殊传送不入图。
- 同一对地图的多个出口保留为不同边，不能只按地图名称去重，否则会丢失“走哪个出口更近”的信息。
- 路线 segment 的目标不是强行站入原始 Warp 源 tile：边界或阻挡的源 tile 转换为从当前方向接近的地图内侧 tile，再由 `Farmer.MovePosition` 的原版碰撞/传送语义触发 Warp；若当前已与源 tile 重叠，则直接校验并触发同一条普通 Warp。

### 距离与规划

- 规划节点是“当前位置/地图入口/地图出口/目的地停车候选”，不是单纯的地图名称。
- 用玩家与马的实际骑乘碰撞语义，在每张地图内计算当前位置到出口、入口到下一出口、最终入口到停车候选的局部路线长度；以这些长度作为边权执行 Dijkstra，得到完整的出口序列和最终停车点。
- 局部路径搜索使用增量预算分帧构建，先完成整条路线计划，再交给骑乘控制器执行。移动期间只消费已确认的当前 segment，不做逐帧全图搜索。
- 局部结果按地图、入口/出口 tile、碰撞体配置和地图签名缓存；同一地图存在多个出口时分别缓存。没有可达停车候选或出口序列时返回明确的不可达结果。

### 生命周期与失效

- 路线计划只属于当前自动导航会话，不写入存档；保存加载、回到标题、地图对象重载、预期 Warp 不匹配或当前 segment 碰撞失败时清除相关图/局部缓存并显式重新规划。
- 地图签名至少包含地图名称、尺寸和普通 `Warp` 元组；局部路径在真正执行前仍用当前 `GameLocation.isCollidingPosition` 再验证，以暴露地图 Mod、动态物体或地图覆盖造成的失效。
- 玩家主动方向输入、菜单暂停、到达最终安全停车点和异常传送分别由自动驾驶状态机处理；路线图本身不改变既有下马跟随状态。

## 依据

- 本地 Stardew Valley `1.6.15.24356` 的地图资源中，当前室外白名单解析出 98 条普通 `Warp` 边；目标地图的连接以 `Town` 为主要枢纽，`Farm`、`BusStop`、`Mountain`、`Forest`、`Beach` 等目标相关地图均存在有向可达路径。
- `GameLocation.updateWarps` 按地图属性 `Warp` 的五字段元组创建原版 `Warp`；`GameLocation.isCollidingWithWarp` 只处理这些普通 Warp。
- 现有 `HorsePathSearch` 已证明固定节点预算、保留 A* frontier、按实际碰撞框搜索的增量模式；骑乘导航沿用该时间/预算边界，但使用独立的玩家碰撞搜索入口。
- [游戏地图与 API 证据](06-game-facts.md)确认了普通 Warp、骑乘室外换图和地图资源版本；[店铺入口与安全停车点](01-destination-anchors.md)提供最终 terminal anchor。
